# AI Notes

I built this with an AI assistant (Claude). This log records what it suggested, what I accepted, and where
my requirements or judgment changed the direction.

## Where AI helped
- Turning the requirements into a phased plan (safety in code → agent → eval → improvement loop → docs).
- Writing most of the code and the deterministic test suite (fake models, so tests need no network or keys).
- Proposing scenario designs, grader checks, the patch schema and the gate criteria.

## Decisions log

| Area | AI suggested | What I decided | Why |
|---|---|---|---|
| Model access | Anthropic API for every role | **Changed:** free tiers only | Free-resource constraint |
| Local models | Ollama as default for high-volume roles | **Changed:** remote free tiers (Groq) by default; Ollama optional per role | Running it shouldn't require installing anything; one free key runs everything |
| Runtime | Python on the host | **Changed:** everything in Docker | Reproducible; no local Python setup |
| LLM library | LiteLLM (my original handoff spec) | **Changed** (AI raised it, I approved): official `openai` SDK against each provider's OpenAI-compatible endpoint | Fewer dependencies in a project that holds API keys. Several public security write-ups reported a compromised LiteLLM PyPI release in March 2026; I didn't verify the details myself, but a smaller dependency surface was the better choice either way |
| Confirmation | (common pattern) a prompt rule "confirm before booking" | **Kept in code:** two-step `propose → confirm(token)`, token valid only after a new patient message | A rule the model can ignore is not a safeguard |
| Tool surface | `confirm_booking` only | Accepted AI's proposal: one `confirm(token)` + `propose_cancel` / `propose_reschedule`; added `act_for_dependent` | One audited write path; fewer tools for the model; dependents were otherwise untestable |
| Model switching | Fallback models on quota errors | **My requirement:** never switch models during an eval; pin per run, checkpoint and resume | A silent switch would make before/after comparisons meaningless |
| Judge model | Gemini, then Groq Llama 3.3 70B | **Changed after `make doctor` returned 404s:** Groq's Llama chat models became Enterprise-only. Judge → `qwen/qwen3.8-27b` (the only non-OpenAI chat family on the free tier); simulator → `gpt-oss-120b`; guard → `gpt-oss-20b` | Keep the judge a different family from both the agent and the simulator it grades; accept the risk that the Qwen model is a preview (documented manual fallback, no silent switch) |
| Model validation | `doctor` pinged each model | **Improved after the 404s:** doctor now tests each role's real job (tool call, emergency flag, JSON) and lists available model IDs on a 404 | A ping can pass while the role would still fail |
| Gate | Allow pre-existing critical violations | **My requirement:** critical violations must be 0 to accept (`--critical-policy no-new` exists but is not the default) | Clinics can't trade a critical failure for an average gain |
| Development | Run against real models while building | **My requirement:** deterministic fake models for all tests; real models only for the eval runs | Reproducibility; API keys never leave the local `.env` |
| Secrets | — | **My requirement:** key never read, printed, logged or committed; traces/errors pass through `redact()` | Basic hygiene |

| Harness concurrency | Parallel trials (2 workers), cancel queued trials on quota | **Bug found in my first real run:** a quota stop cancelled queued futures and `.result()` then raised `CancelledError`, aborting the run. Fixed: never cancel; a stop flag skips unstarted trials; any worker exception becomes an infra-error trial; default is now sequential | One bad trial must never crash the suite; free-tier limits favour sequential runs |

| Simulator | Chat-turn simulator; fidelity check for meta-talk and leaked facts | **Found by reading my first real baseline:** 7 of 26 trials had *role bleed* (the simulated patient wrote the assistant's reply, e.g. "…0900Yes, that works.Your appointment … is confirmed", then ended early). Triage would have sent these to the reflector as agent failures. Fixed: transcript-style prompt, sanitiser that keeps only the patient's own message, `sim_no_role_bleed` check → trial invalid. Two grader blind spots fixed too (re-offering earlier slots after SLOT_TAKEN; "rescheduled" claimed after a new *booking*). I discarded that baseline rather than improve against simulator noise | The eval must not teach the agent to fix the simulator's mistakes |

| Second provider | — | **My request:** add Gemini without touching Groq or the running baseline. Verified model IDs on Google's model page before using them (`gemini-3.8-flash`, `gemini-3.5-flash-lite`, both stable). Provider-layer only: thinking level + max_tokens headroom (thinking counts against the output limit) and passing back Gemini 3 thought signatures (`extra_content`) on tool calls. Groq requests are byte-for-byte unchanged (tested) | Without the signature, Gemini 3 multi-turn tool calls fail; without headroom, small budgets (guard/simulator) could be spent entirely on thinking |

| Date grounding | — | **Found by reading my baseline:** the agent told patients the wrong weekday ("Friday, 17 Oct" — a Saturday; "Friday (13 Oct 2026)" — a Tuesday), once in a trial that still PASSED because the patient corrected it. Added a deterministic `date_consistency` trace check (no LLM) that compares every stated weekday+date with the calendar and with the tools' own `when` labels | A judge reading the chat let it pass; a calendar doesn't |

| Triage & judge (from the clean baseline) | Route every `db_no_collateral` failure to `code_bug`; let the judge's simulator questions see scripted lines | **Fixed after reading the clean baseline:** a wrong-patient booking (parent instead of child) is agent behaviour when that patient was authorized in the session → `prompt_fixable`, still **critical**; only unauthorized collateral is a code bug. The judge's simulator questions now ignore scripted test lines (an injection attempt had invalidated a trial the agent handled perfectly) | Triage must send the right failures to the right owner; a test input is not the simulator misbehaving |

| Local models | 8B Llama simulator next to a 4B Qwen agent | **Changed for a low-memory machine:** `gemma3:4b` simulator (still a different family) so both models stay loaded. Ollama thinking is turned off by default via `reasoning_effort: none` (verified in Ollama's OpenAI-compatibility docs); local calls skip the rate limiter and get a longer timeout; an unreachable Ollama fails fast with a clear hint | No quota means the real before/after loop can finish in hours, not days |

| Closing the loop (run 20261011-144229, rejected) | Keep emergency escalation as model behaviour, graded "eventually" | **Found by reading the rejected run's traces:** after a self-harm disclosure the agent kept verifying/searching for 5–8 turns and escalated late or as "urgent"; a v0 trial still PASSED because the check only asked for escalation *eventually*. Fixed: (1) the runner escalates in code the turn the guard flags; (2) `escalated_emergency` now requires the same turn and nothing after it | In an emergency, delay is the harm; a grader that passes late escalation is grading the wrong thing |
| Gate scoring | Pool targeted passes/valid across scenarios | **Fixed:** the candidate's "22% → 30%" came only from coverage (baseline had 0 valid happy_book_gp trials, candidate 1/1). Like-for-like it was 2/9 vs 2/9. Targeted rates now use only scenarios valid on both sides; exclusions are reported | An improvement must not come from measuring different things |
| Reflector output | Discard a patch that breaks the 300-char limit | **Fixed:** the right fix for the linked-child critical was lost at 315 chars. Length-only failures are now shortened once by the reflector and re-linted; the report shows the original | The limit protects the prompt; it shouldn't throw away the best candidate |
| Judge | Goal only | **Fixed:** the judge now sees the persona (an injection persona insisting is in character) and is told urging emergency care isn't medical advice; asking for an alternative after "unavailable" isn't leaving the goal | Two trials were invalidated or failed for behaviour that was correct |
| Code bugs triage surfaced | — | **Fixed by me in code (not by the loop):** `search_slots` could never show afternoon slots (first page was all morning) → `part_of_day` filter; DOB "03-02-1984" was rejected and retried 8× → readable formats accepted, ambiguous day/month asked about (never guessed, so no wasted identity attempt), identical failing calls not re-run; wrong weekdays → a 4-week calendar table in the prompt | These are code bugs; a playbook patch could only hide them |

| All-local judge (llama3.1:8b) | Keep the same judge criteria with a smaller local judge | **Found by reading the first all-local baseline (20261011-170747-v0) before running the loop:** the 8B judge failed our own code-written emergency message as "medical advice", failed "confirmed before write" while quoting the confirmation question, and failed criteria with evidence "n/a". Fixed: `confirmed_before_write` is now a deterministic trace check (date + time read back after proposing, before confirm); a judge FAIL with no evidence or quoting a code-written message is "not evaluated". `make regrade` re-applies code-side grading to a finished run from its traces, with no model calls (3 false failures flipped; every real failure kept) | Move every criterion code can check out of the judge; a weaker judge makes this more important, not less |

| Weak local reflector (run 20261011-175437) | Trust lint + gate to filter whatever the 8B coach proposes | **The gate worked:** candidate 3 (an example with an invented "Dr. Smith" and a read-back with no date) lifted the targets 17% → 50% but taught the agent to skip the date; `medical_advice` regressed and was confirmed on re-run → rejected. **Then I fixed the tooling around the coach, not the agent:** lint now rejects doctor names and single-specialty rules; the reflector prompt explains each failing check, asks for root causes and different checks per patch, and requires examples to use placeholders and follow every rule; a resumed run now refuses a playbook whose *content* differs even when the version number matches | A weak proposer needs a stricter filter and clearer instructions; the gate is the reason a bad patch cost time, not quality |

| Final outcome | Keep looping until something is accepted | **My decision:** stop after the second loop. Loop 1's best candidate was rejected on a confirmed regression; loop 2's candidates didn't beat a fresh baseline. I report that as the result rather than loosen the gate after seeing the numbers | Changing acceptance rules to get a "win" would make the before/after meaningless |

## Things I checked rather than trusted
- Every safety guarantee has a deterministic test (`tests/test_tools_*.py`).
- The judge's evidence quotes are verified against the transcript before a failure is trusted.
- Held-out scenarios are blocked from the reflector in code (and tested).
